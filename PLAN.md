# План: клиент Яндекс Книги для Amazon Kindle

Автономное нативное приложение-клиент сервиса **Яндекс Книги**
(Bookmate/Букмейт) для старых устройств **Amazon Kindle** (e-ink, jailbroken).

Источники, на которых основан план:
- API-обёртка (референс): https://github.com/stepan163s/yandex-book-api
- Kindle dev: https://kindlemodding.org/kindle-dev/index.html

---

## 0. Зафиксированные решения

| Параметр | Решение | Последствие |
|---|---|---|
| Размещение | **Полностью автономный клиент** — всё на устройстве | Нет бэкенда: OAuth, вызовы API, резолв контента, сборка и чтение книги — на Kindle |
| Устройства | **K5 (Kindle 5-го поколения, 2012) и старше** (K4, Kindle Keyboard/K3 …) | Очень слабый ARM, ~256 МБ RAM, старая glibc/busybox, e-ink 600×800, у большинства **нет тача**, навигация 5-way + кнопки |
| Аудио | **Нет** (MVP — только текст) | Не нужен аудио-стек; фокус на ридере |
| UI | **Свой UI** | Не KOReader — собственный рендер и навигация под e-ink |

Эти решения делают проект **нативным приложением на C/C++**, кросс-собранным
под старый Kindle. Python-библиотека `yandex-book-api` используется **как
спецификация** эндпоинтов, а не как рантайм на устройстве.

---

## 1. Цель

На устройстве Kindle (K5 и старше), без внешнего сервера:
1. Авторизоваться в Яндекс Книгах (токен, см. §6).
2. Смотреть свою библиотеку/полки и искать книги.
3. **Читать текстовые книги** на e-ink с пагинацией, шрифтами, сохранением
   позиции и синхронизацией прогресса.

---

## 2. Критические ограничения и риски (прочитать первым)

### 2.1. Доступ к контенту книг — риск №1 ⚠️
`yandex-book-api` покрывает **метаданные** (библиотека, полки, поиск,
профиль, статистика, прогресс), но **не** содержит методов скачивания
**текста книги** — контент отдаётся приложениям Яндекса по отдельному
недокументированному протоколу чтения (последовательность документов-глав;
ср. `bookmate_downloader`). Значит, ядро приложения — не UI, а **получение
и расшифровка контента**, и в автономной модели это надо делать **на
устройстве, на C**. Требуется разведка (Фаза 0) до основной разработки.

**Правовой аспект:** работаем только с легальным доступом самого пользователя
(его подписка/покупки, его токен). Это надо явно зафиксировать.

### 2.2. TLS/HTTPS со старого устройства — риск №2 ⚠️
Серверы Яндекса требуют современный TLS 1.2+/актуальные шифры и валидный набор
корневых сертификатов. Штатный сетевой стек Kindle 2011–2012 гг. **не
договорится** с ними (старые шифры, устаревший CA-бандл). Поэтому приложение
должно **нести свой сетевой стек статически**: `libcurl` + `mbedTLS`
(или `OpenSSL`) + **свежий CA-бандл**, всё кросс-собранное. Это конкретный
блокер, планируемый на раннюю фазу (как это делает KOReader).

### 2.3. Устройство K5-и-старше
- **CPU/RAM:** слабый ARM (Freescale i.MX), ~256 МБ. Нельзя грузить всю книгу
  в память — потоковая обработка и постраничная пагинация.
- **glibc старая:** кросс-компиляция под целевой toolchain (Meson +
  cross-file); статическая линковка тяжёлых зависимостей.
- **E-ink 600×800, 16 градаций серого:** без анимаций/скролла, только
  постраничное обновление; partial refresh для навигации + периодический
  full refresh против гостинга. Вывод через штатный `eips` или прямой
  framebuffer (`/dev/fb0`).
- **Ввод зависит от модели:** K3 — аппаратная QWERTY + 5-way; K4/K5 — 5-way
  контроллер + кнопки листания, **без тача и клавиатуры**; Kindle Touch — ИК-тач.
  → UI проектируем под **5-way + кнопки** как общий знаменатель, тач/клавиатура
  опционально.
- **Сеть:** нестабильный Wi-Fi → офлайн-кэш обязателен.
- **Jailbreak + KUAL:** нужен джейлбрейк, hotfix (переживает OTA), KUAL как
  лаунчер.

---

## 3. Целевое устройство MVP

«K5 и старше» — это диапазон с разным вводом и разрешением. Предлагается
выбрать **одно ведущее устройство** для MVP (напр. **Kindle 4/5 non-touch** —
самый массовый общий знаменатель: 5-way + кнопки, 600×800), довести на нём до
рабочего состояния, затем портировать на остальные модели диапазона.
→ Финальный выбор ведущей модели — за заказчиком (см. §10).

## 4. Архитектура: слоёное нативное приложение (всё на устройстве)

```
┌──────────────────────────── Kindle (K5 и старше) ────────────────────────────┐
│                                                                              │
│  UI-слой (e-ink)                                                             │
│   framebuffer/eips рендер · навигация 5-way/кнопки · экраны                  │
│                                                                              │
│  Reader-движок                                                              │
│   парсинг EPUB/FB2 · FreeType (шрифты) · перенос строк · пагинация ·        │
│   позиция чтения                                                            │
│                                                                              │
│  Домен / модель данных                                                      │
│   Book, LibraryCard(progress,state), User, Bookshelf · кэш · офлайн-хранилище│
│                                                                              │
│  Yandex-клиент (порт нужного подмножества yandex-book-api на C)              │
│   REST + GraphQL · JSON (cJSON) · резолв и расшифровка контента книги        │
│                                                                              │
│  Сетевой слой (несём с собой, статически)                                    │
│   libcurl + mbedTLS/OpenSSL + свой CA-бандл                                  │
│                                                                              │
│  Хранилище токена/конфига (файл на устройстве)                               │
└──────────────────────────────────────────────────────────────────────────────┘
                                  │ HTTPS
                          ┌───────▼────────┐
                          │ Яндекс Книги    │
                          │ REST + GraphQL  │
                          └────────────────┘
```

Всё, что раньше предлагалось выносить на бэкенд, теперь реализуется на
устройстве на C. Python-библиотека — только источник знаний об эндпоинтах,
моделях и GraphQL-запросах, которые мы **переписываем на C**.

## 5. Технологический стек

- **Язык:** C (ядро/сеть/парсинг) + при желании C++ для UI. Сборка **Meson**
  с cross-file под целевой toolchain (рекомендация kindlemodding для нативной
  разработки).
- **Сеть/TLS:** `libcurl` + `mbedTLS` (лёгкий, хорошо статически линкуется) +
  собственный `cacert.pem`.
- **JSON:** `cJSON` (маленький, без зависимостей).
- **Шрифты/текст:** `FreeType` для растеризации; собственный алгоритм переноса
  строк и пагинации под ширину экрана.
- **EPUB/FB2:** распаковка zip (`miniz`) + разбор XHTML/FB2-XML (лёгкий парсер).
- **Дисплей:** `eips` (штатная утилита) для простого вывода, либо прямой
  `/dev/fb0` для полного контроля refresh.
- **Ввод:** чтение `/dev/input/event*` (5-way, кнопки, тач).
- **Упаковка:** расширение KUAL (menu.json + бинарник) для запуска.

Всё тяжёлое — статически, чтобы не зависеть от старой glibc устройства.

---

## 6. Аутентификация без браузера

Полноценный OAuth-браузер на e-ink неудобен, а на K4/K5 ещё и без клавиатуры.
Для автономного клиента:
- **MVP:** токен `y0_...` кладётся в **конфиг-файл на устройстве через USB**
  (пользователь получает токен на компьютере по стандартному OAuth-URL Яндекса
  и копирует в файл). Приложение читает токен из файла, валидирует
  (`test_token`), хранит локально.
- **Позже (опц.):** ввод токена/логина на устройстве через экранную клавиатуру
  (навигация 5-way) — трудоёмко, поэтому вне MVP.

---

## 7. Интеграция с API (порт на C)

Из `yandex-book-api` берём как спецификацию и переписываем на C нужное
подмножество:

- **Метаданные/библиотека:** `get_book`, `get_my_library` (пагинация),
  `get_my_bookshelves`, `get_user_books`, `add_book`/`remove_book`.
- **Профиль/служебное:** `get_profile`, `test_token`, `get_sync_state`.
- **Поиск:** GraphQL-endpoint (точный запрос уточнить по исходникам библиотеки).
- **Прогресс чтения:** чтение/запись состояния (`LibraryCard.progress/state`,
  `sync_state`).
- **Контент (Фаза 0):** эндпоинты протокола чтения → расшифровка → сборка во
  внутреннее читаемое представление (EPUB/FB2 в памяти/кэше).

Модели: Book (uuid, title, annotation, cover, authors), Image, Person,
LibraryCard (progress 0–100%, state), User, Bookshelf.

---

## 8. UI/UX под e-ink (свой UI, навигация 5-way)

- Постраничные экраны, без скролла и анимаций; фокус-элемент подсвечивается,
  перемещается 5-way, кнопки листания = страницы.
- Экраны MVP: **Библиотека** → **Карточка книги** → **Читалка**; **Поиск**;
  **Настройки/статус токена**.
- Высокий контраст, крупный шрифт, обложки с dithering под 16 градаций серого.
- Refresh-стратегия: partial при навигации, full периодически.

---

## 9. Данные, кэш, офлайн

- Локальное хранилище: скачанные/собранные книги, метаданные, позиции чтения,
  токен. Кэш метаданных, чтобы не дёргать сеть постоянно.
- Синхронизация прогресса: устройство → Яндекс (`sync_state`), правило
  «последний по времени выигрывает».
- Память: не держать всю книгу в RAM — постраничная подгрузка глав.

## 10. Этапы разработки

### Фаза 0 — Разведка осуществимости (блокирующая) 🔬
1. **Контент:** как приложение Яндекса получает текст книги под токеном
   пользователя; воспроизводимо ли это и во что собирать. Правовые рамки.
2. **TLS с устройства:** собрать статический `libcurl`+`mbedTLS`+CA и
   **проверить успешный HTTPS-запрос к Яндексу с реального K5/K4**.
3. **Toolchain:** поднять кросс-сборку Meson и запустить «hello, framebuffer»
   на устройстве.
- **Go/No-Go:** если контент недоступен или TLS невозможен — переопределить
  продукт (например, только просмотр библиотеки/метаданных без чтения).

### Фаза 1 — Каркас нативного приложения
- Кросс-сборка, KUAL-запуск, вывод на e-ink, обработка ввода 5-way.
- Сетевой слой (TLS) + JSON + чтение токена из конфига (`test_token`).

### Фаза 2 — Данные и навигация
- Порт API-вызовов на C: библиотека, полки, поиск.
- Экраны Библиотека/Поиск/Карточка книги на своём UI.

### Фаза 3 — Reader-движок (ядро)
- Резолв и расшифровка контента (по итогам Фазы 0).
- Парсинг EPUB/FB2, FreeType, перенос строк, пагинация, позиция чтения.
- Синхронизация прогресса.

### Фаза 4 — Полировка
- Офлайн-кэш, устойчивость к обрывам Wi-Fi, обложки под e-ink, память.
- Порт на остальные модели диапазона (разные ввод/разрешение).

## 11. Открытые вопросы (уточнить у заказчика)

1. **Ведущая модель MVP** внутри «K5 и старше» (Kindle Touch с тачем vs
   K4/K5 non-touch с 5-way vs K3 с клавиатурой)? От неё зависят ввод,
   разрешение и toolchain.
2. Подтверждаем правовые рамки: работаем только с легальным доступом
   пользователя под его токеном?
3. Способ ввода токена в MVP — **файл через USB** — приемлем?

## 12. Первый шаг

**Фаза 0**, три параллельные проверки: (1) получение контента книги под токеном,
(2) успешный HTTPS к Яндексу со своим TLS-стеком на реальном устройстве,
(3) рабочая кросс-сборка + вывод на e-ink. Любая из проверок может стать
блокером — поэтому делаем их до основной разработки.
